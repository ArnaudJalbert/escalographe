# Data sources and provenance

L’Escalographe collects public observations without claiming that a mapped escalator works. No source is affiliated with this project.

## STM

- Organization: Société de transport de Montréal (STM).
- Verified public source: STM's [French escalator status index](https://www.stm.info/fr/infos/etat-du-service/ascenseur), with equipment on [station detail pages](https://www.stm.info/fr/infos/etat-du-service/ascenseur/station-peel). This was server-rendered HTML when inspected on October 19, 2026. The [developer catalog](https://www.stm.info/fr/a-propos/developpeurs) did not document an escalator JSON API.
- Retrieval: backend HTTP client and HTML parser, not a browser-side scrape. The index gives station summaries, while detail pages contain individual segments and directional reports. Do not equate a station-level warning with an identified device outage; parse equipment details. Source markup can change. Keep source URL, informal French segment labels, raw status, and observation time when available. STM provides no OSM IDs or coordinates for these items.
- Refresh target: about every 5 minutes. Treat observations as potentially stale after about 15 minutes. Record failed attempts separately, retain the last successful statuses, and do not classify missing data as an outage.
- Authority: operational status for STM escalators, not all escalators in the city. STM's network extends beyond the City of Montréal. STM status pages have no device coordinates. The map uses separately sourced station centroids and explicitly labels them approximate.
- Station geography: the official [STM GTFS feed](https://www.stm.info/sites/default/files/gtfs/gtfs_stm.zip) supplies 68 `location_type=1` station coordinates. The checked-in, attributed station snapshot was extracted from feed version `20261007130000_26N`. The City of Montréal membership test uses [OSM relation 1634158 geometry via Nominatim](https://nominatim.openstreetmap.org/lookup?osm_ids=R1634158&format=geojson&polygon_geojson=1), not a bounding rectangle. Station coordinates are stored separately from escalator coordinates. Refresh these versioned snapshots when station locations or city boundaries change; the five-minute STM status refresh does not re-download a 67 MB GTFS archive.
- Attribution and rights: identify STM and link back to its public status page. STM's [GTFS/API data terms](https://www.stm.info/fr/a-propos/developpeurs/condition-dutilisation) describe CC BY 4.0 for those feeds, **not necessarily for escalator HTML**. Its [general website notice](https://www.stm.info/fr/notes-juridiques) restricts reproduction of site content. Publish derived factual statuses rather than copied prose or logos, and seek STM clarification about systematic reuse. This independent project is not endorsed by STM.

## OpenStreetMap / Overpass

- Organization: [OpenStreetMap contributors](https://www.openstreetmap.org/copyright); queries run through the [Overpass API](https://dev.overpass-api.de/overpass-doc/en/more_info/components.html).
- Retrieval: backend Overpass client, approximately daily, with a timeout, bounded retries, exponential backoff, and a descriptive User-Agent. Query [City of Montréal relation 1634158](https://api.openstreetmap.org/api/0.6/relation/1634158), an `admin_level=8` administrative boundary verified on October 19, 2026, as an Overpass area; do not use a handmade rectangle. Overpass area generation can lag the OSM relation. Station-level STM statuses must not be attached to arbitrary nearby OSM ways.
- Discovery: `highway=steps` and `conveying=*` are primary escalator tags. Preserve OSM type and ID, coordinates or geometry, useful tags (levels, indoor, incline, conveying direction, name, operator, building, and access) when present. The [OSM conveying tag documentation](https://wiki.openstreetmap.org/wiki/Key:conveying) explains direction values. These tags describe map features, **not current operational state**.
- Authority: geometry and metadata, not live status. An OSM-only escalator is `unknown`. Reconcile with STM conservatively; nearby devices are not automatically the same physical machine. `conveying=forward/backward` follows OSM way geometry, not STM's `montant/descendant` equipment direction.
- Operational caveat: several public Overpass attempts during initial research failed with HTTP 403/406 or timeouts. A later local run on October 19, 2026 succeeded against `overpass-api.de` and returned **74 real escalator records** within the city boundary. Availability can change by request. If Overpass fails, the adapter labels its three-record direct [OSM main API bbox](https://api.openstreetmap.org/api/0.6/map?bbox=-73.569,45.502,-73.562,45.507) fallback `partial_downtown_sample`; that sample does **not** represent city-wide coverage. Preserve existing full-city records and distinguish provider errors from genuinely empty results.
- License and attribution: [OpenStreetMap data are available under ODbL](https://www.openstreetmap.org/copyright). Display "© OpenStreetMap contributors" and a copyright/license link on maps and wherever OSM data are reused. The project's MIT code license does not replace OSM's data license. Honor the tile provider's usage policy separately.

## Interpreting the atlas

Status values are `operational`, `out_of_service`, `verification_needed`, and `unknown`; raw source text remains attached. Freshness is separate. Coverage counts records with a meaningful live status, whereas current availability excludes unknown records from its denominator. Historical reliability starts when this service begins collecting observations and cannot reconstruct earlier events from a current-status feed. A source failure leaves the prior observation in place and marks its age; it is not proof of equipment failure.
