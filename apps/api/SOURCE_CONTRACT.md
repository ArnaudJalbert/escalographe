# Source adapter contract

Implement `app.adapters.outbound.stm.source.StmEscalatorSource` and `app.adapters.outbound.osm.source.OsmEscalatorSource`. Each has an async `fetch() -> app.ports.SourceSnapshot`. `app.bootstrap.use_cases()` imports them lazily; neither adapter should import FastAPI or SQLAlchemy. Constructors currently take no arguments.

`SourceSnapshot(source: str, records: tuple[ExternalEscalatorRecord, ...], fetched_at: timezone-aware datetime, metadata: dict = {})`. `ExternalEscalatorRecord` fields in order: `source`, `external_id`, `name`, `station_name`, `location_description`, `status` (`app.domain.Status`), `source_status`, `latitude`, `longitude`, `direction`, `from_level`, `to_level`, `municipality`, `within_montreal`, `source_url`, `raw_data` (JSON-compatible dict), `observed_at` (timezone-aware UTC datetime). Use source names `stm` and `osm`; external IDs must remain stable per physical equipment. OSM coordinates should be factual geometry/center; STM coordinates and city-membership must remain `None` unless sourced, not inferred from a station name. Use `Status.UNKNOWN` for OSM (metadata only). Preserve the French STM status label as `source_status`, parsed directional rows as separate records, and source URL per equipment.

A fetch/parse/network failure should raise, not emit an empty snapshot or synthesized outages. The use case records the failure in a separate transaction; previous statuses remain unchanged. Refreshes are atomic. STM status and freshness are independent; `observed_at` must be the *source retrieval time*, not a guessed source update time. For Montréal geography use OSM relation 1634158, not a bounding box. The city-default catalogue includes records with unknown city membership so STM status remains visible, but their `within_montreal` remains `null` and they cannot be counted as confirmed city locations. The bootstrap imports each adapter lazily and independently so API startup and the other provider can run if one source module is unavailable.
